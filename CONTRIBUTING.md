# Contributing

## Scope

- Keep a change focused on the lab or repository maintenance task it addresses.
- Preserve the purpose and provided materials of existing labs. Do not rewrite embedded Git-history fixtures unless the task calls for it.
- Update the root lab index when adding, removing, or renaming a lab.
- Keep instructions reproducible and identify the directory from which commands must be run.

## Changes and review

- Use a descriptive branch and commit message that explain the change.
- Describe the problem, the change, and the verification performed in the pull request.
- Run the checks documented by the affected lab. If a check cannot be run, say why and report the expected result separately from the actual result.
- Keep generated files, local IDE settings, credentials, and machine-specific data out of commits.

## Documentation

- Keep each lab's README close to its materials and update it when behavior or required steps change.
- Use relative links for files in this repository and verify that their targets exist.
- Preserve the language and terminology of existing course materials unless the task requests a translation.
